# 多平台草稿

本功能从 v3.6.0 起提供；已安装版本是否具备此功能，以 `capabilities --json` 为准。源码工作区可先 `make build`，再使用 `./md2wechat` 运行下列命令。

CLI 在本地准备正文，宿主 Agent 复用用户已登录的浏览器，按照内置步骤创建、保存并重新打开草稿。当前步骤覆盖知乎、CSDN、头条；不包含公开发布。准备成功不等于草稿完成。

## 使用

```bash
md2wechat capabilities --json
md2wechat sync prepare article.md --output ./article-prepared --json
md2wechat skills read md2wechat references/sync/workflow.md --json
md2wechat skills read md2wechat references/sync/zhihu.md --json
# 其他目标：references/sync/csdn.md、references/sync/toutiao.md
```

`--output` 必须是父目录已存在的新目录。唯一生成文件是 `body.html`，原稿和图片不修改、不复制、不上传。返回 `SYNC_PREPARED`、`status: action_required`，`data` 包含有效标题、正文文件绝对路径、去重后的本地图片路径、正文标题级别和 `execution_owner: host_agent`。失败返回 `SYNC_PREPARE_FAILED`，不应开始远端写入。

成功结果的 `message` 会直接给出公共流程和目标平台的 `skills read` 命令。这些命令读取当前二进制内置说明，无需用户同步更新本地 `SKILL.md`；Agent 按返回指引读取本次目标即可。

支持普通 Markdown 的段落、标题、列表、引用、代码和表格，以及本地 PNG、JPEG、GIF、WebP 图片。优先读取 frontmatter 的 `title`，否则使用首个 Markdown 标题。缺失标题、空正文、无效 frontmatter、缺失或无效图片、未生成图片、未解析 Obsidian 语法、原始 HTML 和高级排版块会被拒绝。远程图片须先另行保存为本地文件并调整原稿引用；此命令不下载图片，也不要求微信凭证或排版 API Key。

## 宿主执行

### 示例：把一篇文章同步到知乎和头条草稿箱

向 Agent 提供文章路径并说明目标，例如：“把 article.md 保存到知乎和头条草稿箱，使用我已经登录的账号。”若文章、账号或是否公开发布不明确，先补齐对应信息；本流程只支持未发布草稿。

Agent 先读取当前 CLI 的公共流程和两个目标说明，并检查浏览器是否可用：

```bash
md2wechat skills read md2wechat references/sync/workflow.md --json
md2wechat skills read md2wechat references/sync/zhihu.md --json
md2wechat skills read md2wechat references/sync/toutiao.md --json
md2wechat sync prepare article.md --output ./article-prepared --json
```

同一篇未改动的文章只准备一次；如果已经取得成功准备结果，直接复用。输出目录必须尚不存在，已有结果不覆盖。准备失败时先解决原稿或素材问题，不打开编辑器写入。

Agent 读取返回的标题、正文文件和图片路径，按各平台限制分别判断是否能继续。随后在指定账号中上传图片、填写正文和标题、保存草稿，取得草稿地址并重新打开核对。知乎完成后再处理头条；某个平台受阻不抹去另一个平台已完成的结果。比如正文有 H2 和 H3，头条应暂停并说明层级限制，不能擅自改稿。

最后分别报告两个平台的账号、草稿地址、重开核对结果和未完成原因。“本地准备完成”或“已点击保存”不能作为同步完成的结论。中途失去连接时，恢复原草稿继续操作，不重新创建；此版本也不会自动更新用户此前发表的文章。

### 浏览器要求

优先使用当前 Agent 的浏览器能力，复用已登录会话。宿主缺少必要能力时，可检查 agent-browser 作为备选；连接条件、安装边界和同稿恢复统一见内置公共流程。不默认下载独立浏览器，也不要求所有用户安装同一种扩展。agent-browser 的三平台富文本、图片和重开闭环尚未验证，不能据工具已安装宣称可完成草稿。

固定流程是逐图正常上传、读取已插入正文的图片地址、替换待粘贴 HTML 中对应图片引用、在唯一正文区域正常粘贴、最后填写并核对标题、保存、取得唯一草稿地址、重新打开核验全文。直接改 `innerHTML` 不属于正常编辑；不可用内部业务请求替代平台编辑器。

先读公共流程，再读目标平台说明；具体定位方式、上传窗口和恢复步骤以当前 CLI 内置说明为准。DOM 或可访问性结构必须与说明相符，布局变化时停止并报告，不猜测点击位置。

头条会把粘贴的标题归一成一级标题。单一标题级别可按此已知差异处理；含多个级别的文章应在写入前停止，须经用户同意调整源稿后重新准备。不能把层级丢失算作成功。保存后还需逐字符核对特殊字符；发现丢失且无法修复时停止该目标，不能擅自删改原稿。一次字符丢失不足以推导整类字符不可用。

## 结果与恢复

完成标准是指定账号上的未发布草稿，重新打开后标题、全文、图片位置及主要结构均符合预期。点击保存、看到一个地址或只检查首尾，都不能替代全文核对。

宿主用普通本地进度笔记记录目标账号、原稿路径、已知草稿地址、最后确认的步骤和未解决问题。没有 `record`、`status` 命令，也没有回执或交付包系统。操作中断或结果不明时，先重新打开已有地址或查看草稿列表，确认后继续同一草稿，不盲目重复创建。笔记中的私人账号、草稿地址和临时图片地址不提交到公共仓库。

## 维护与新增平台

在已授权测试账号上跑通正常编辑器后，再增加目标平台说明。仅记录执行需要的入口、账号核对、唯一控件定位、输入限制、图片插入、保存信号和同稿恢复方式；复用公共流程，不重复通用规则。

验证短图文、结构、长文及中断恢复，将日期、环境、样本和结果记在已有 [SMOKE.md](SMOKE.md)，不写入 Skill 或其操作参考。将会改变操作选择的已知限制提炼为规则，不能把单次失败推导为整类禁用。

新增平台时更新 Skill 的目标入口及公共流程中的目标名称，确认 `skills read` 可以读取平台说明。只有命令能力改变才修改能力输出，不新增登记文件或执行框架。
